# Project state — what actually works (2026-10-13)

**Milestone:** On `main`: vertical slice 1, Keycloak SSO (EPI-003) and demo Keycloak. EPI-006 Jira collector (PR #4), screenshots (PR #6), EPI-007 GitLab collector, EPI-008 identity mapping & admin screens, EPI-004b organization admin, scheduled daily sync, audit-log viewer, offline bundle (EPI-012a), production sign-in with AD via bundled Keycloak (EPI-003b). Demo uses synthetic data. Not production-ready (no real Jira/GitLab connected, no offline bundle).

## Working and verified (tests in `TEST_STATUS.md`)

- **One-command demo:** `./epi.sh demo` builds the image, starts PostgreSQL + EPI via Compose (localhost only), migrates, seeds labeled synthetic data, waits for `/health/ready`. `doctor`, `start/stop/status/logs`, `backup`, `restore` verified.
- **KPI engine (pure, unit-tested):** Cycle Time, Work Item Aging (median/P85/oldest), Review Waiting Time (per reviewer request) and the separately coded proxy `MR_OPEN_TO_FIRST_REVIEW`; confidence classes (N/A < 5, low 5–9, normal ≥ 10); window-over-window trend from raw observations, ±8% exploratory threshold, zero-baseline guard.
- **Data model:** migration for hierarchy, effective-dated memberships/roles/grades, identities, ingestion tables, assessments, KPI snapshots, audit, sessions.
- **SSO (EPI-003):** Keycloak/OIDC sign-in (code + PKCE, state, nonce, browser binding, no token storage, no auto-provisioning), IdP logout, production mode gated on OIDC + https. Verified against a real ephemeral Keycloak (API integration + browser E2E). See `KEYCLOAK.md`.
- **Jira DC collector (EPI-006):** read-only REST client (paging, retries, timeouts), relative-time incremental JQL with 48 h overlap and 6-month backfill, status mapping by ID (inferred + admin override), metadata-only idempotent upserts, safe cursor, one run per connection; CLI `jira-add/check/sync`; admin API for integrations, sync runs and status mappings. Verified against a fake Jira DC (see `JIRA.md`).
- **GitLab collector (EPI-007):** read-only REST v4 (`read_api`), MRs + reviewer requests/notes/approvals as metadata only, bot/self exclusion, Jira-key links with confidence, `updated_after` incremental with overlap, CLI `gitlab-add/check/sync`, admin sync dispatch. Feeds Review Waiting Time end to end. See `GITLAB.md`.
- **Administration (EPI-008):** admin-only screens for integrations (Sync now, run history), identity mapping (map/unmap Jira & GitLab accounts to people, re-attributing synced data, audited), status mappings and data quality (freshness, coverage, link rate, unmapped statuses). Verified end to end with `scripts/e2e-admin.sh`.
- **Organization administration (EPI-004b):** groups/teams (create, rename, move, deactivate), people (create, edit, deactivate with session revocation), dated memberships and transfers, roles with scope validation, grades; admins cannot change their own roles; ≥1 admin always remains; all audited, nothing deleted.
- **Scheduled daily sync (ADR-021):** admin-set local hour + IANA time zone (off by default) on the Integrations tab / `GET|PUT /api/v1/admin/sync-schedule`; in-process minute timer runs all enabled Jira/GitLab connections sequentially, once per local day (DB claim — safe with several processes, DST-safe, same-day catch-up), failures isolated, audited; `EPI_SYNC_SCHEDULER=off` disables it.
- **Audit-log viewer (ADR-022):** admin-only, read-only Audit log tab and API; filter by action group/exact action, person and dates; keyset paging; review subjects and text never shown.
- **Offline installation (EPI-012a, ADR-023):** images pinned by digest; `./epi.sh bundle` and `./epi.sh offline-install` (checksums, image identity check, bundled images only); verified by `scripts/test-offline-install.sh` on a no-egress Docker network incl. refusal of corrupted/tampered bundles. Production dependency licenses checked in CI (216 packages, all permissive).
- **Production sign-in with AD (EPI-003b, ADR-025):** `./epi.sh sso-setup` + `deploy/compose.sso.yaml` — Keycloak in production mode with its own database, read-only LDAPS federation limited to pilot team groups, bind password in Keycloak's file vault, customer CA trust. Verified end to end against a synthetic LDAPS directory (`scripts/e2e-sso-ldap.sh`); not yet against the real AD.
- **Data retention (ADR-032):** daily deletion of source activity, sync history, KPI snapshots and audit entries older than 24 months (`EPI_RETENTION_MONTHS`), expired sessions at any age; assessments and people kept; audited; `retention --dry-run` CLI; shown on Administration › Data quality.
- **Upgrade with automatic rollback (EPI-012c, ADR-031):** `./epi.sh upgrade <bundle>` — bundle verification, version checks, database (and Keycloak) backup, image load, file swap, migrations on start, health check; on failure the previous files, database and version come back. Verified by `scripts/test-upgrade.sh` (upgrade, refusals, broken release rolled back with data intact).
- **AD team import (EPI-004c, ADR-030):** Administration › Directory maps configured AD team groups to EPI teams; preview shows every change (new people, e-mail links, detail updates, joins/transfers, leavers, skipped conflicts) and apply runs exactly the previewed plan (hash, advisory lock, one transaction, audited). `directory-check` CLI verifies AD access. Verified against the synthetic LDAPS directory (unit, integration, browser and deployed-container tests).
- **Demo SSO:** bundled dev-mode Keycloak with generated per-install users (`./epi.sh credentials`).
- **Auth & RBAC:** opaque server-side sessions (HttpOnly, SameSite=Lax, CSRF header for mutations); demo login only in demo mode. Scope resolution from EPI DB; out-of-scope = 404; small-group suppression (default 5) for aggregate-only viewers; admin sees structure but not KPIs/reviews.
- **API:** `/health/*`, `/api/v1/me`, organization tree, groups/teams/developers, KPI cards + catalog + explanation, reviews (list, create/update/submit), demo auth. OpenAPI/Swagger at `/api/docs`.
- **UI:** single React app — context-aware home, org → group → team → developer drill-down with breadcrumbs, KPI cards with sample/confidence/freshness/trend, "How calculated?" drawer, monthly assessment form, loading/empty/error/not-found/suppressed states, responsive (desktop + mobile tested), light/dark, localization catalog.
- **Ops scaffolding:** `scripts/ci.sh` (local CI), `.gitlab-ci.yml` for an internal runner, fallback secret scan, hourly resume scheduler scripts (**not enabled**).

## Not implemented yet / known limitations

- Not yet run against the real AD (needs the owner's server, bind account and CA); `sso-apply` for realm changes after first start; Keycloak DB not in `./epi.sh backup`; TLS front end is the customer's.
- No real Jira/GitLab connected (needs B1–B6); deleted-issue reconciliation; sprint data.
- `install` (EPI-012) exits 2 with a message (use `offline-install`). Bundle signing; clean-VM offline test.
- KPIs computed on request; `kpi_snapshots` not populated yet. Stratification by work type/complexity not shown in UI yet.
- Audit-log retention policy and export (needs owner decision on retention period).
- Hebrew catalog not written (structure supports it). `PUT /reviews/{id}` replaced by idempotent `POST` upsert.
- No SBOM/vulnerability scan yet (needs approved scanner, C11).
